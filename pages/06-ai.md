# Case Study: Bun

The JavaScript runtime, rewritten from Zig to Rust in May 2026.

::left::

### Why

Some of the bugs fixed in a single release:

- use-after-free crash in `node:zlib`
- double-free crash in the CSS parser
- memory leak in `crypto.scrypt`
- a passphrase leaked on error paths

::right::

### How

- **535,496** lines of Zig, ported by Claude
- Then about **16,000** compiler errors
- `cargo check` became a **work queue**: per crate, 1 agent fixes and 2 more review
- **11 days**, 6,778 commits, about **$165k** of tokens
- **100%** of ~60,000 tests passing, none skipped or deleted

<!--
- Disclosure, same as the blog post makes: Bun was bought by Anthropic in Dec 2025, and Jarred works there. Treat it as a case study, not an independent benchmark.
- Why: these are real items from the v1.3.14 changelog. Use-after-free, double-free, forgot-to-free - exactly what ownership rules 2 and 3 make into compile errors. Zig has `defer`, but you have to remember it at every call site; Rust has Drop.
- They already ran ASAN on every commit, fuzzed 24/7, had leak tests. Still got these bugs.
- [clicks]
  - Jarred's estimate: 3 engineers with full context, about a year. So they would never have done it by hand.
  - The 16,000 errors came after splitting the code into ~100 crates (for compile speed) and fixing cyclic dependencies. "A massive number for 1 human, but not a crazy number for 64 claudes at once."
  - The loop: run cargo check once per crate, group the errors by file, one agent fixes, two "adversarial" reviewers in separate contexts try to find bugs, one more applies the feedback.
  - Compile time hurt them too: they banned cargo and git inside the porting loops because slow commands stalled everything. Same cost as on the GUILT slide.
  - The test suite is written in TypeScript, so it didn't depend on the language Bun was written in - that's what made it possible to trust.
- Results in v1.4: 128 bugs fixed, a 3 MB-per-build memory leak gone, ~20% smaller binary, 2-5% faster. Claude Code has run on the Rust version since June.
- Source: bun.sh/blog/bun-in-rust
-->

# Using Rust Doesn't Make Vibe Coding Safe

- `.unwrap()` everywhere (remember Cloudflare)
- `.clone()` just to keep the borrow checker quiet
- `unsafe` added into code without asking
- Logic bugs: well-typed code that does the wrong thing

<!--
- Balance: the compiler checks memory and types, not intent.
- Left [clicks]:
  - "Let's get all the crates to compile" was read as "delete the parts that don't". It compiles! It does nothing.
  - Jarred's fix was a rule for the reviewers: "If you need a paragraph-long comment to justify why the workaround is OK, the code is wrong - fix the code."
  - Best regression example: Zig's `assert` is a function, so its argument always runs. Rust's `debug_assert!` is a macro that's removed in release builds - and the ported code had a side effect inside it. Hot reload broke in release builds only. Both versions look identical.
  - 4% unsafe: mostly single lines calling into C++ (JavaScriptCore). The upside is that it's greppable - Zig has no unsafe keyword at all.
- Right [clicks]: the general ways AI-written Rust goes wrong. All of them compile. unwrap is the Cloudflare outage from the Result slide; clone-spam works but wastes the point of borrowing; todo!() panics at runtime.
- [click] So you still need tests and you still need review. The compiler raises the floor, it doesn't replace either.

# My Setup: GAVMO

George's Agent Virtual Machine Orchestrator

- Boots a disposable **NixOS VM** per repo, and runs the coding agent inside it
- The agent can only write to the repo: no `sudo`, no access to the rest of my machine
- API keys stay on the host, and the agent calls tools through a gateway
- Control panel written in **Leptos**
- Around 27k lines
- 90% test coverage

![GAVMO repo](https://opengraph.githubassets.com/1/GeorgeRoe/gavmo){.w-xs}

# Make The Compiler Aggressive

::left::

```toml
# GAVMO's Cargo.toml (trimmed)
[workspace.lints.rust]
unsafe_code = "deny"
unused_must_use = "deny"

[workspace.lints.clippy]
unwrap_used = "warn"
expect_used = "warn"
panic = "warn"
todo = "warn"
indexing_slicing = "warn"
allow_attributes_without_reason = "warn"
```

::right::

- CI runs clippy with `-D warnings`, so any warning blocks the build
- Turning a lint off needs a reason someone can review:
  ```rust
  #[expect(
      clippy::similar_names,
      reason = "uid/gid are the conventional names"
  )]
  ```

<!--
- Clippy is Rust's official linter - it comes with rustup. The left is a trimmed version of GAVMO's real config.
- Every item here is something from earlier in the talk, turned into a hard rule:
  - unsafe_code: memory safety is the default, and any exception has to be declared.
  - unused_must_use: you can't ignore a Result (from the Result slide).
  - unwrap_used / expect_used / panic: no Cloudflare-style crashes - errors have to be returned, like in GUILT.
  - todo: no stubbed-out functions slipping through - Bun's mistake from the last slide.
  - indexing_slicing: `v[i]` can panic, so use `.get(i)` and handle the Option.
- (Tests are exempt via clippy.toml - panicking is fine there.)
- [clicks]
  - An agent that reaches for unwrap gets an error in its own loop and has to fix it properly before I ever see the code.
  - `#[expect]` instead of `#[allow]`: it needs a reason, and it warns if the lint stops firing, so stale opt-outs get cleaned up.
  - The only unsafe in GAVMO is in crates/vm/src/process.rs: Linux syscalls (prctl, kill) with no safe std wrapper. Even that module opts out with `#![expect(unsafe_code, reason = "prctl(PR_SET_PDEATHSIG) and kill(2) have no safe std API")]`. Easy to find, easy to review.
  - Also in CI: overflow checks in release builds, cargo-deny for dependency advisories, and a coverage floor that only ever goes up.
- The takeaway for you: AI means one person can build far more. But someone still has to read it, and Rust makes the important parts - what can fail, what gets changed, what's unsafe - visible in the code. Learning to read Rust is still worth it.
-->
